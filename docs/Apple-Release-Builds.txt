Signed Apple builds (GitHub Actions)
====================================

.github/workflows/apple-builds.yml builds, signs and distributes the Apple apps.
The Release workflow (.github/workflows/release.yml) runs it on every push to
master, together with the Windows and Linux builds; it also runs by hand
(Actions > Apple builds > Run workflow):

- Mac app: Developer ID signed with the hardened runtime, notarized and
  stapled; a .zip that opens on any Apple silicon Mac without warnings. The
  bundled Homebrew libraries come from the runner (macOS 26), so the CI build
  needs macOS 26 or later.
- iPhone / iPad: an ad-hoc .ipa, uploaded to Firebase App Distribution.
- Apple Vision Pro: an ad-hoc .ipa (Firebase App Distribution has no visionOS
  install flow; install it with Apple Configurator or
  "xcrun devicectl device install app").

Each run keeps all three as workflow artifacts. The ad-hoc builds install on the devices registered with the
Apple developer team when they were built. The builds contain no ROMs.

Versions and releases
---------------------
Every push to master gets the next version: CANNONBALL_DX_VERSION in
src/main/globals.hpp plus a release number (1.04 gives 1.04.1, 1.04.2, ...;
raising CANNONBALL_DX_VERSION starts again at .1). The Apple apps carry that
version (CFBundleShortVersionString; CFBundleVersion is the run number). When
the Apple, Windows and Linux builds all pass, the Release workflow tags the
commit vX.Y.N and publishes a GitHub release with the Mac .zip, both .ipa
files, the Windows .zip and the Linux .tar.gz. A failed or cancelled run (a
newer push cancels the one in progress) tags nothing.

Secrets and variables
---------------------
The workflow's header lists every secret and variable it reads. They follow
the owner's SigningSecrets tool (signing certificates, App Store Connect API
key, Firebase service account), which sets them from the login keychain.

Firebase App Distribution
-------------------------
Firebase project: outrun-cannonball-dx (console.firebase.google.com). Each
build is uploaded there. To invite testers automatically:

1. Firebase console > App Distribution > Testers & Groups: add testers to a
   group.
2. Set the repository variable FIREBASE_GROUPS to the group's alias (or
   several, comma-separated). A manual run can name groups instead.

Testers open the email invite on their iPhone or iPad, which registers its
UDID with Firebase; the next run copies new UDIDs to the Apple developer
account (fastlane sync_devices) so that build installs on them.

Branding
--------
Release builds use the default CannonBall DX name and icon. A local
apple-overrides.cmake (git-ignored) only affects local builds; CI sets just
the signing team and the bundle ID (.github/scripts/apple-overrides.sh).
